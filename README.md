# АПО.ТИМИМО — аудит установленного программного обеспечения

**Версия:** 0.1.1 (MVP)  
**Разработка:** команда КАИРО  
**Разработчик:** Иващенко Сергей Сергеевич  
**Логотип:** предоставлен автором проекта, включён в окно «О программе» и ресурсы приложения  
**ОС:** Windows 10/11, macOS, Linux  
**Режим:** локальный, без сервера, аккаунта или доступа к сети. Программа *не изменяет* установленные приложения.

## Сведения о программе

- **Название:** АПО.ТИМИМО.
- **Назначение:** аудит установленного программного обеспечения на одном компьютере.
- **Разработка:** команда КАИРО.
- **Разработчик:** Иващенко Сергей Сергеевич.
- **Версия:** 0.1.1.
- **Логотип:** исходный файл `software_audit/assets/logo-original.png`; адаптированные PNG используются в главном окне, окне «О программе» и как значок приложения там, где Tkinter/ОС его поддерживает.

В главном окне нажмите **«О программе»** для просмотра сведений. Вкладка **«Сведения об установленном ПО»** предназначена для подробностей выбранной программы и не является окном информации о самом приложении.

## Возможности

- Поиск установленных программ и пакетов, версий, издателей и путей установки (если источник их предоставляет).
- Поддержка нескольких локальных источников данных на каждой ОС.
- Поиск, фильтр по источнику, сортировка, карточка подробных сведений.
- История в виде сжатых снимков; сравнение нового и предыдущего сканирования: добавлено / удалено / смена версии.
- Экспорт **CSV** (открывается в Excel), **JSON**, **HTML** (печать в PDF через браузер), **PDF** (если установлен ReportLab).
- Встроенный терминальный режим для автоматизации без GUI.

## Установка и запуск

Требуется **Python 3.10+** с модулем `tkinter`. Основные функции не требуют сторонних Python-пакетов.

### macOS

1. Установите Python с [python.org](https://www.python.org/downloads/macos/) (в комплект входит Tkinter); если Python уже установлен, проверьте: `python3 -m tkinter`.
2. Распакуйте ZIP в папку.
3. Откройте Terminal и перейдите в папку `software-audit`:
   ```bash
   cd /путь/к/software-audit
   python3 -m software_audit
   ```
   Или запустите `run_macos_linux.command` (двойной щелчок может потребовать разрешить запуск в настройках безопасности).

### Windows

1. Установите Python 3.10+ с [python.org](https://www.python.org/downloads/windows/) и включите Python Launcher (`py`).
2. Распакуйте архив и откройте `run_windows.bat`, либо запустите в PowerShell в распакованной папке:
   ```powershell
   py -3 -m software_audit
   ```

### Linux

1. Нужны `python3`, `python3-tk` (в некоторых дистрибутивах отдельно) и графическая среда.
2. В распакованной папке: `python3 -m software_audit`.

### Экспорт PDF (необязательно)

```bash
python3 -m pip install -r requirements-optional.txt
```

На Windows вместо `python3` используйте `py -3`. Без ReportLab доступны CSV/JSON/HTML; HTML можно открыть и распечатать в PDF.

## Как пользоваться

1. Нажмите **Сканировать**. Сканирование macOS через `system_profiler` может быть длительным; опцию можно выключить на вкладке «Настройки сканирования».
2. Используйте поиск, фильтры и сортировку. По клику на строку выводятся подробные сведения.
3. На вкладке «Изменения» сравнивайте программы с **последним сохранённым сканированием**.
4. Нажмите **Экспорт отчёта** и выберите формат файла. Экспорт учитывает текущий фильтр таблицы.

Снимки хранятся **локально** в `~/.software-audit/snapshots/` (до 25 штук), содержат имена программ, версии и пути установки; это может быть чувствительной информацией. Вы можете удалить эту папку вручную, если больше не нужна история. Запросы на серверы не отправляются.

## Какие источники проверяются

| ОС | Источники |
|---|---|
| Windows | HKLM/HKCU Uninstall Registry, 32/64-битные представления; Microsoft Store (`Get-AppxPackage`) |
| macOS | `/Applications`, `/System/Applications`, `~/Applications`, `/Library/Applications`; `system_profiler SPApplicationsDataType -json`; Homebrew Formula/Cask |
| Linux | `dpkg-query`, `rpm`, `pacman`, `flatpak`, `snap`, если установлены |

## Консольный режим

Запустите в корне проекта:

```bash
python3 -m software_audit.cli scan --save-history --format json --output programs.json
python3 -m software_audit.cli scan --format csv --output programs.csv
python3 -m software_audit.cli scan --format html --output programs.html
python3 -m software_audit.cli scan --format pdf --output programs.pdf
python3 -m software_audit.cli scan --without-profiler --without-store
python3 -m software_audit.cli history
python3 -m software_audit.cli compare
```

По умолчанию, если нет `--output`, полный JSON выводится в stdout, а сообщения сканирования — в stderr. Возврат 0 означает успех без предупреждений; 1 — сбор завершён с предупреждениями; 2 — ошибка экспорта/сравнения.

## Важные ограничения

1. **Это инвентаризация, а не сертифицированный аудит безопасности.** Проверка CVE, обновлений, лицензий и цифровых подписей пока не реализована; не делайте выводов о безопасности только по этому списку.
2. Сканирование ограничено доступными системными источниками и разрешениями. **Не все программы обязательно будут найдены**: portable EXE, некоторые AppImage, приложения в нестандартных каталогах, ПО других учётных записей.
3. macOS обычно не предоставляет надёжную дату установки или издателя через `Info.plist`. Пустые поля — это *нет данных*, а не ошибка. В Linux поле «издатель» для `dpkg` показывает сопровождающего пакет (Maintainer), что не всегда означает разработчика исходного ПО.
4. Пакетные менеджеры Linux могут включать зависимости и библиотеки, не только графические приложения.
5. Один и тот же продукт может встречаться в разных источниках (например, Homebrew Cask и `.app`). Точные дубликаты объединяются; остальные могут отображаться отдельно.
6. История сравнивает локальные снимки: при смене имени, пути или идентификатора ПО может выглядеть удалённым и заново установленным. При неполном сканировании результаты сравнения могут быть неточны.
7. Программа не выполняет установку/удаление ПО и не отправляет данные по сети. Реестр Windows читается; `Win32_Product` не используется, чтобы не вызывать побочных эффектов MSI.
8. Поле **дата установки** появляется только если его отдаёт системный источник (например, ключ реестра Windows). Даты изменения файлов нельзя считать датами установки.

## Сборка в отдельное приложение (опционально)

На **целевой** ОС установите PyInstaller (`python3 -m pip install pyinstaller`) и соберите:

```bash
python3 -m PyInstaller --noconfirm --windowed --name APO_TIMIMO --icon software_audit/assets/app-icon.icns --add-data "software_audit/assets:software_audit/assets" launcher.py
```

На macOS эта команда использует фирменный значок `app-icon.icns`. На Windows используйте следующий вариант с `app-icon.ico`:

```powershell
py -3 -m PyInstaller --noconfirm --windowed --name APO_TIMIMO --icon software_audit/assets/app-icon.ico --add-data "software_audit/assets;software_audit/assets" launcher.py
```

Команды используют входящий в проект `launcher.py`. Это только инструкция: сборку нужно выполнять и проверять на **целевой ОС**, она ещё не создана. Отдельный исполняемый файл для Windows нельзя собрать и проверить на macOS или Linux с гарантией работоспособности.

## Разработчику

Главный модуль сбора — `software_audit/collector.py`, модели — `models.py`, сохранение снимков — `storage.py`, экспорт — `export.py`, графический интерфейс — `gui.py`. Все источники выполняются только в локальном режиме с ограничениями времени запуска системных команд. Код не требует прав администратора для обычного аудита.

## Готовые пакеты и автоматическая сборка для трёх ОС

Инструкции и сценарий сборки настоящих Windows `.exe`, macOS `.app` (Apple Silicon/Intel) и Linux-архива находятся в [BUILDING.md](BUILDING.md). Для каждой ОС создана отдельная цель в `.github/workflows/build-native.yml`. **Доступность исходного кода и сценария сборки сама по себе не означает наличие готовых исполняемых файлов для каждой ОС**: их нужно собрать на соответствующих системах. Для Debian 13 x64 предусмотрен отдельно протестированный пакет со встроенным интерпретатором Python.
